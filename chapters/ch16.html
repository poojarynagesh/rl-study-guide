Deep Q-Network: Human-level Video Game Play

DQN (Mnih et al., 2013, 2015) is Q-learning with a deep convolutional network as the action-value function, fed with raw game pixels. Plain Q-learning with a nonlinear approximator is unstable; DQN tames it with experience replay, a periodically frozen target network and error/reward clipping. One architecture and one set of hyperparameters learned 49 different Atari games.

16.5.1 Why Q-learning with a deep network?

Unless the state set is small enough for a lookup table, a value function needs a parameterised approximator, whether linear or nonlinear. Function approximation depends on features that convey the information needed for skilled play, and most successful RL applications relied on handcrafted features built from human knowledge of the specific problem. DeepMind showed that a deep multi-layer ANN can automate feature design.

  • Multi-layer ANNs have been used in RL since backpropagation was popularised (1986; see §9.7). TD-Gammon is the classic success: TD-Gammon 0.0 with an almost "raw" board input matched the best earlier programs; adding handcrafted backgammon features (TD-Gammon 1.0) made it much better. So even the best earlier demonstrations needed specialised input features.
  • DQN = Q-learning + a deep convolutional ANN (convolutional layers for spatial arrays such as images — see §9.7). Goal: high performance on any of a collection of different problems without problem-specific feature sets.
  • DQN learned 49 Atari 2600 games through an emulator. A separate policy per game (network weights reset to random before each game), but the same raw input, network architecture and parameter values (step size, discount, exploration schedule, …) for every game. The CNN turns the common raw input into features specialised for the action values of whichever game it is learning.

Why Q-learning specifically?
  • Using TD-Gammon's afterstates for Atari would need the next state for every action: one-step emulator simulations for each action (possible with ALE) or a learned model — more complicated and slower.
  • Model-free and off-policy: and experience replay requires an off-policy algorithm (updates need not follow connected trajectories). Q-learning fits both.
From the lectures: neural-network approximators and the activation function Nov 2

Single-hidden-layer network built step by step: encode state $i$ as $x(i)=(x_1(i),\dots,x_d(i))$; first linear layer $\sum_{l=1}^dw_{kl}x_l(i)$ for $k=1..K$; pass each through a nonlinearity $\sigma$; aggregate with a second linear layer:

$$\hat v\big(x(i),w\big)=\sum_{k=1}^{K}w_k\,\sigma\Big(\sum_{l=1}^{d}w_{kl}\,x_l(i)\Big)$$

$w$ collects all $w_k$ and all $w_{kl}$ ($K+Kd$ numbers; e.g. $d=3$, $K=4$ gives $4+12=16$). The weights do not depend on the state — a new state only gives a new input vector; there is one network, not one per state, and training is done once, not repeated per state. "Hundreds to a few thousand" parameters is perfectly manageable.

Requirements on $\sigma$: differentiable, monotonically increasing, bounded. Examples: tanh (range $(-1,1)$, $\tanh 0=0$), sigmoid $1/(1+e^{-\xi})$ (range $(0,1)$, $\sigma(0)=\tfrac12$). ReLU $\max(0,\xi)$ is used in deep nets but is not differentiable at 0 (left derivative 0, right derivative 1) and unbounded; smoothed variants (e.g. GELU, mentioned as an aside) fix the kink. Differentiability matters because the TD update needs $\nabla_w\hat v$ via the chain rule.

TD with a network is the same semi-gradient update as before: $w_{t+1}=w_t+\alpha[R_{t+1}+\gamma\hat v(X_{t+1},w_t)-\hat v(X_t,w_t)]\nabla_w\hat v(X_t,w_t)$. Number of layers, neurons per layer and activations are design decisions.

16.5.2 The DQN setup on Atari 2600

The Atari 2600 (sold 1977–1992; Pong, Breakout, Space Invaders, Asteroids) is a popular RL testbed thanks to the publicly available Arcade Learning Environment (ALE). DQN's choice of testbed was also inspired by TD-Gammon's human-level play.

From the lectures: the setting — partial observability, history as state, $\gamma$, returns Nov 2

The agent sees only the current screen $x_t$ of the emulator, so Atari is partially observed: the emulator's internal state is hidden. The lecture therefore takes the history as the state, $s_t=(x_1,a_1,x_2,a_2,\dots,a_{t-1},x_t)$, $s_{t+1}=(s_t,a_t,x_{t+1})$ (in practice this is the preprocessed stack $\phi(s_t)$). Tasks are episodic (games end in a finite random time).

Discount $\gamma=0.99$. Since the tasks are episodic $\gamma=1$ would also be admissible; a value slightly below 1 was used for better stability, since an expert may keep a game going for a long time. Return $G_t=\sum_{t'=t}^{T-1}\gamma^{t'-t}R_{t'+1}$ (upper limit $T-1$ in Sutton–Barto indexing, where the last reward is $R_T$). Target of learning: $Q^*(s,a)=\max_\pi\E[G_t\mid S_t=s,A_t=a,\pi]$, which satisfies the Bellman optimality equation $Q^*(s,a)=\E_{s'}[R+\gamma\max_{a'}Q^*(s',a')\mid s,a]$. A network with weights $\theta$ approximating $Q^*$ is a Q-network.

Notation: the book writes $\hat q(s,a,\mathbf w)$ and $R_{t+1}$; the DQN paper and the lectures write $Q(s,a;\theta)$ and $r_t$. Same objects.

16.5.3 The Q-learning update, loss and gradient

Ignoring Mnih et al.'s modifications for a moment, DQN used the semi-gradient form of Q-learning:

$$\mathbf w_{t+1}=\mathbf w_t+\alpha\Big[R_{t+1}+\gamma\max_{a}\hat q(S_{t+1},a,\mathbf w_t)-\hat q(S_t,A_t,\mathbf w_t)\Big]\nabla\hat q(S_t,A_t,\mathbf w_t)$$
Semi-gradient Q-learning with a network(16.3)

$S_t$, $S_{t+1}$ are the preprocessed image stacks; the gradient is computed by backpropagation. It is semi-gradient because the target $\max_a\hat q(S_{t+1},a,\mathbf w_t)$ depends on $\mathbf w_t$ but that dependence is ignored — exactly as in §9.3.

Two practical techniques from large-network training: a mini-batch method (weights updated after accumulating gradients over a small batch — 32 images — for smoother sample gradients) and RMSProp (Tieleman & Hinton 2012), which adapts the step size per weight from a running average of the magnitudes of recent gradients for that weight.

DQN target, loss and gradient (with the frozen target network)

Target (paper notation, parameters $\theta^-$ of the target network):

$$y=\begin{cases}r&\text{if the next state is terminal}\\ r+\gamma\max_{a'}Q(s',a';\theta^-)&\text{otherwise}\end{cases}$$

Loss at iteration $i$, expectation over tuples sampled uniformly from the replay memory $D$:

$$L_i(\theta_i)=\E_{(s,a,r,s')\sim U(D)}\Big[\big(r+\gamma\max_{a'}Q(s',a';\theta_i^-)-Q(s,a;\theta_i)\big)^2\Big]$$

Only $Q(s,a;\theta_i)$ depends on $\theta_i$; the target term uses $\theta_i^-$, so its gradient w.r.t. $\theta_i$ is zero:

$$\nabla_{\theta_i}L_i=-\,2\,\E\Big[\big(r+\gamma\max_{a'}Q(s',a';\theta_i^-)-Q(s,a;\theta_i)\big)\nabla_{\theta_i}Q(s,a;\theta_i)\Big]$$

Stochastic gradient descent on one sampled tuple (factor 2 absorbed into $\alpha$):

$$\theta_{i+1}=\theta_i+\alpha\Big[r+\gamma\max_{a'}Q(s',a';\theta_i^-)-Q(s,a;\theta_i)\Big]\nabla_{\theta_i}Q(s,a;\theta_i)$$

Plain Q-learning (16.3) is recovered by setting $\theta^-=\theta$ and sampling the latest transition.

Pitfalls in the update
  • The max is taken with the target network at the next state $s'$, not the online network and not at $s$.
  • Do not backpropagate through the target: $\theta^-$ is a constant when differentiating.
  • At a terminal transition the target is just $r$ — the bootstrap term is dropped.
  • The "+" in the update comes from $-\nabla(-Q)$: gradient descent on the squared error looks like ascent in the TD-error direction.
From the lectures: deriving the loss and the SGD update Nov 2

The expectation in $\nabla L_i$ cannot be computed in the model-free setting (transition probabilities unknown), so drop it and use realised samples drawn from the replay buffer — stochastic gradient descent. The exact gradient step is $\theta_{i+1}=\theta_i-\alpha\nabla L_i=\theta_i+\alpha\E[2(\text{target}-Q)\nabla Q]$; the minus from differentiating $-Q(s,a;\theta_i)$ combines with the descent sign to give a plus. The lecturer's remark: index by the iteration $i$, not by the time step $t$, since each iteration uses a sampled tuple, not the latest one.

16.5.4 The three modifications to Q-learning

Mnih et al. changed basic Q-learning in three ways (plus engineering: mini-batches, RMSProp, reward clipping, 4-frame stack).

1. Experience replay

(Lin, 1992.) After the emulator executes $A_t$ in the stack $S_t$ and returns $R_{t+1}$ and $S_{t+1}$, DQN adds the tuple $(S_t,A_t,R_{t+1},S_{t+1})$ to the replay memory, which accumulates experience over many plays of the same game. At each time step, multiple Q-learning updates — a mini-batch — are performed on experiences sampled uniformly at random from the memory. The next update does not use $S_{t+1}$ as its $S_t$; a new, unconnected experience is drawn. This is legitimate because Q-learning is off-policy and need not follow connected trajectories.

Advantage of replayWhy
Data efficiencyeach stored experience can be used for many updates
Lower variancesuccessive updates are not correlated with one another, unlike standard Q-learning along a trajectory
Less instabilityremoves the dependence of successive experiences on the current weights (which action is taken now shapes the next data) — eliminates one source of instability
From the lectures: replay in detail — the buffer, one tuple at a time, questions from class Nov 2 & Nov 4

Experience $e_t=(S_t,A_t,R_{t+1},S_{t+1})$; the data set grows $D_t=\{e_1,\dots,e_t\}$ but in practice the buffer has a limited capacity $N$ (capital $N$): keep only the most recent $N$ tuples, discard older ones (you cannot store everything, as the number of iterations is not known in advance). A tuple is drawn uniformly: with $T$ stored tuples each has probability $1/T$ — so the latest tuple is picked with probability only $1/T$ (e.g. $1/20$ if 20 are stored).

Loop as drawn in class: realise a tuple → store it first → sample from the buffer → update $Q$ → act ($\varepsilon$-greedy w.r.t. the new $Q$) → store the next tuple → sample again. Student questions answered: (i) nothing is discarded except old tuples when the buffer is full; (ii) only realised experiences are ever in the buffer — an unrealised tuple cannot show up; a tuple may be re-sampled many times; (iii) stored tuples generally have different states, actions, rewards and next states (they are not one trajectory); (iv) in the simplified version the update uses one tuple at a time; the implementation uses a mini-batch.

Contrast with original Q-learning: only the latest tuple $e_t$ was used, immediately. With replay: store, then sample.

2. The target network

The target $\max_a\hat q(S_{t+1},a,\mathbf w_t)$ is a function of the same parameters being updated, unlike supervised learning where targets do not depend on the parameters — this can cause oscillations and/or divergence (Chapter 11). Fix: whenever $C$ updates of $\mathbf w$ have been done, copy the current weights into a duplicate network and hold them fixed for the next $C$ updates. The duplicate network's output $\tilde q$ supplies the targets for those $C$ updates:

$$\mathbf w_{t+1}=\mathbf w_t+\alpha\Big[R_{t+1}+\gamma\max_{a}\tilde q(S_{t+1},a,\mathbf w_t)-\hat q(S_t,A_t,\mathbf w_t)\Big]\nabla\hat q(S_t,A_t,\mathbf w_t)$$
Update with a duplicate (target) network $\tilde q$ — fixed for $C$ updates§16.5

This brings Q-learning closer to the supervised case (a stationary target for a while) while still bootstrapping.

Right after a copy the lag is 0; just before the next copy it is $C-1$ updates. So $\theta^-$ lags the online weights by between $0$ and $C-1$ updates (not always $C$).

From the lectures: why a frozen target helps — time-scale argument Nov 2 & Nov 4

If the target parameter changed at every step, you would be trying to track the expected target under a parameter that moves on the same time scale as the thing you are learning — very hard. Freezing it for $C$ steps makes the target piecewise stationary. At the next reset both networks again solve the same problem. Implementation wording (Nov 4): "every $C$ updates the DQN network is cloned to obtain the target network $\hat Q$, which then generates the targets $y_j$ for the next $C$ updates".

3. Error clipping

The error term $R_{t+1}+\gamma\max_a\tilde q(S_{t+1},a,\mathbf w_t)-\hat q(S_t,A_t,\mathbf w_t)$ is clipped to $[-1,1]$ before it multiplies the gradient: values above $+1$ become $+1$, below $-1$ become $-1$, others unchanged. This also improved stability. (It is separate from reward clipping in §16.5.2, which clips the reward to $\{-1,0,+1\}$.)

From the lectures: why clip Nov 4

The error can become very large, positive or negative, which is undesirable for the gradient step; clipping bounds the size of any single update. (Equivalent view, not stated in class: clipping the error corresponds to a squared loss inside $[-1,1]$ and an absolute-value loss outside — the Huber loss.)

Other details of Mnih et al. (2015) not in the book

  • Frame skip: the agent selects an action only every $k=4$-th frame and repeats it on the skipped frames; the emulator's frames between are not seen by the network. This is why "50 million frames" in the paper's learning-time statement means agent steps, see below.
  • The paper takes the pixel-wise maximum over two consecutive frames before extracting luminance, to remove sprite flicker.

16.5.6 Why plain Q-learning with a network is unstable

Q-learning with a nonlinear approximator (a neural net) can oscillate or diverge — the $Q$ values may blow up. In Sutton & Barto's terms it combines the three ingredients of the deadly triad (Chapter 11): (1) function approximation, (2) bootstrapping, (3) off-policy training. Linear on-policy TD is stable (§9.4); the triad together is not guaranteed to be.

Source of troubleDQN's remedy
Successive samples are strongly correlated (same trajectory), and depend on the current weightsExperience replay: uniform random sampling from a large buffer
The target $\max_a\hat q(S',a,\mathbf w)$ moves every time $\mathbf w$ changes (target depends on the parameters being learned)Target network frozen for $C$ updates
Large errors give large gradient steps; reward scales differ across gamesReward clipping $\{-1,0,+1\}$, error clipping $[-1,1]$
Tiny changes in $Q$ can flip the greedy action (large policy change)Smoother, decorrelated, mini-batch updates (see box)
Exam trap

The target network does not remove the deadly triad — it reduces instability from the moving target. Replay does not make learning on-policy; it deliberately uses old, off-policy data, which is why an off-policy algorithm is required. And neither fixes partial observability.

From the lectures: the three causes of instability Nov 2

The DQN authors first diagnosed why Q-learning with a network diverges, then proposed remedies. Three causes:

  1. Correlation between successive observations. One sample is $(S_t,A_t,R_{t+1},S_{t+1})$, the next $(S_{t+1},A_{t+1},R_{t+2},S_{t+2})$: the end state of one is the start state of the next, and the next state depends on the current state and action. Consecutive samples are dependent. Fix: experience replay.
  2. Small changes in $Q$ can cause large changes in the policy. Board example with actions $a_1,a_2$: at time $t$, $Q(a_1)$ is slightly higher so the max picks $a_1$; at $t+1$ the values change slightly, $a_2$ is now slightly higher, and the chosen action jumps to $a_2$ — oscillations.
  3. Correlation between the action values and the target values. Minimising $\big(Q(s,a)-[r+\gamma\max_{a'}Q(s',a')]\big)^2$, the same $Q$ (same parameters) sits in the estimate and in the target, so one gradient step changes both — you are chasing a dynamically moving target. Fix: target network.
From the lectures: tutorial recap — problems and fixes Nov 20

The TA's list of what goes wrong with neural networks in RL: (1) correlated samples — given $(S_t,A_t)$ the next state is largely determined, and $A_{t+1}$ follows from $S_{t+1}$ (analogies: a batter weak against a bowler who plays offensively tends to get out; a student with one day left who does not study tends to fail); (2) the agent stays in one region of the state space during training; (3) unstable targets — a small weight change can cause a large change in Q-values, and the target is built from the same network, so it moves with every update.

Fix 1 — replay buffer: store transitions, sample randomly from all stored data; the sampled next state need not relate to the state–action pair just seen, breaking the correlation. Fix 2 — target network: two networks $\theta$ (online) and $\theta^-$ (target), $\theta^-_0=\theta_0$; for a period of $N$ updates change $\theta$ only; then copy $\theta$ into $\theta^-$. The update is $Q_{t+1}(S,A)=Q_t(S,A)+\alpha[R+\gamma\max_{A'}Q^-_t(S',A')-Q_t(S,A)]$ — the max uses the target network at the next state. The target stays fixed for a while; after the copy both networks solve the same problem again.

Class example (flow only, no numbers computed): $Q(S,A)=2$, $Q(S,B)=4$, $Q^-(S,A)=3$, $Q^-(S,B)=5$, target period 2 updates: $Q_1$ and $Q_2$ are computed from $Q_0$ while $Q^-_1=Q^-_2=Q^-_0$, then $Q^-_2$ is overwritten by $Q_2$. Exam guidance: expect mostly numerical questions plus short derivation-style parts reusing tricks; the TA's advice was to learn the tricks, not memorise proofs.

Note: this tutorial uses $N$ for the target-update period; in the lectures and paper that is $C$, and $N$ is the replay capacity.

Ablation: which design features mattered?
  • Runs on 5 games with the four combinations of {replay, duplicate target network} included or not: each alone significantly improved performance, and together dramatically.
  • Deep convolutional DQN vs a network with just one linear layer on the same stacked frames: the improvement of the deep CNN was particularly striking on all 5 games.

Limitations (the book's closing remarks)

  • Not one agent that excels at all tasks at once — learning was separate for each game.
  • Not a complete solution to task-independent learning: all games were played from video, which made a deep conv-net a natural choice.
  • Some games fell well short of human skill. The hardest — e.g. Montezuma's Revenge, where DQN did about as well as the random player — need deep planning beyond what DQN was designed for.
  • Learning control by extensive practice is only one kind of human learning.

16.5.8 Partial observability and DRQN

The book notes that the full states of many Atari games are not completely observable from a single frame; stacking four frames "did not eliminate partial observability for all the games, but it was helpful in making many of them more Markovian". Atari is therefore effectively a POMDP. The natural next step is to give the Q-network memory. (The DRQN paper is beyond §16.5 of the book; the content here is from the lectures.)

From the lectures: DRQN — Deep Recurrent Q-learning for POMDPs Nov 4

POMDP: the agent gets only partial information about the state; the screen is a surrogate for it. DRQN (Hausknecht & Stone, AAAI 2015 — spelling of authors as heard in class) builds on DQN: the algorithm is the same; only the network architecture changes — a recurrent network (with feedback, which allows more processing of a layer; in the paper an LSTM layer after the convolutional layers) replaces the feed-forward CNN. Recurrency helps when the quality of observations changes over time.

  • On standard Atari games DRQN performs similarly to DQN.
  • Flickering games: at each step the screen is fully obscured with some probability (observed with probability $p$, obscured with $1-p$). When trained on normal games and evaluated on flickering ones, DRQN does better than DQN.

Exam status per the professor: the DQN paper should be read carefully; DRQN is optional, "out of personal interest".

16.5.9 Summary

  • DQN = semi-gradient Q-learning + deep convolutional network on $84\times84\times4$ preprocessed frames, 18 outputs (one $\hat q$ per action).
  • Experience replay (uniform samples from the last $N$ tuples; needs off-policy) decorrelates and reuses data; a target network frozen for $C$ updates stabilises the bootstrapped target; clipping (reward to $\pm1$, error to $[-1,1]$) standardises scales and bounds updates.
  • Target $y=r+\gamma\max_{a'}Q(s',a';\theta^-)$ ($y=r$ if terminal); gradient only through $Q(s,a;\theta)$.
  • The same architecture and hyperparameters learned 49 games; ≥75% of human on 29 of 46. Weak on games needing deep planning (Montezuma's Revenge).
  • DRQN replaces the feed-forward net by a recurrent one for partial observability.

Self-test

Why did Mnih et al. choose Q-learning rather than TD($\lambda$) with afterstates as in TD-Gammon?

Afterstates are not available for Atari (they'd need next-state simulation for every action or a learned model); Q-learning is model-free and off-policy, which experience replay requires.

Describe the network input and output of DQN.

Input: four stacked preprocessed frames, $84\times84\times4$ (luminance). Output: 18 units, one estimated optimal action value $\hat q(s,a,\mathbf w)$ per action (4–18 valid per game). Hidden: 3 conv layers (32 $20\times20$, 64 $9\times9$, 64 $7\times7$ maps) then 512 fully connected ReLU units.

Write the DQN target and the gradient step. What is held fixed?

$y=r+\gamma\max_{a'}Q(s',a';\theta^-)$ ($=r$ at termination); $\theta\leftarrow\theta+\alpha[y-Q(s,a;\theta)]\nabla_\theta Q(s,a;\theta)$. $\theta^-$ is held fixed (no gradient through the target) for $C$ updates.

Give three benefits of experience replay.

Each experience reused for many updates (efficiency); successive updates uncorrelated (lower variance); breaks the dependence of the data on the current weights (removes a source of instability). It needs an off-policy method.

In which ranges does $\theta^-$ equal which $\theta$, for period $C$?

$i\in[0,C-1]\Rightarrow\theta_0$; $[C,2C-1]\Rightarrow\theta_C$; $[2C,3C-1]\Rightarrow\theta_{2C}$; … It lags by 0 to $C-1$ updates.

What exactly is clipped to $[-1,1]$, and what to $\{-1,0,1\}$?

The TD error is clipped to $[-1,1]$ (stability); the reward (change in score) is clipped to $+1,0,-1$ (same scale for all games).

Name the three causes of instability the lecture identified and the matching fix.

(1) Correlated successive observations — replay. (2) Small $Q$ changes flipping the greedy policy — the lecture gave no separate fix; mini-batch averaging and the frozen target damp it. (3) Correlation between $Q$ and its own target (moving target) — target network.

Which three ingredients make up the deadly triad and which of them does DQN have?

Function approximation, bootstrapping, off-policy training. DQN has all three, so it needs the stabilising tricks.

What did the ablation show?

Replay and the target network each help alone, and together dramatically; the deep conv net was strikingly better than a single linear layer on the same inputs.

Why does stacking four frames help, and does it solve partial observability?

One frame lacks velocity/history information; four frames make many games more Markovian. It does not eliminate partial observability for all games — hence DRQN with a recurrent layer.

How does DRQN differ from DQN, and where does it win?

Same algorithm, recurrent architecture. Similar on standard Atari; better when trained on normal games and tested on flickering (randomly obscured) ones.

What kind of games does DQN fail at, and why?

Those needing deep planning, e.g. Montezuma's Revenge (about random-player level); rewards are sparse, so learning from reward-driven bootstrapped targets with epsilon-greedy exploration never finds the goal.
